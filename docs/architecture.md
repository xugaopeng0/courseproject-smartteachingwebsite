# 架构与扩展边界

## 当前架构

浏览器 → nginx / React → Go API → MySQL 8.4 + Qdrant + 私有文件卷。

讲义上传 → MySQL 持久化任务 → 非 root worker（Poppler / LibreOffice）→ 课程网关嵌入 → Qdrant。MySQL、Qdrant、API 和 worker 只在 Compose 内网通信；嵌入与（后续的）对话只从服务端调用课程网关，凭证不下发浏览器。

```text
浏览器 ──> web（nginx，唯一发布 127.0.0.1:8080）──> api（Go）
                                                     ├─ db      MySQL 8.4：账号、班级、讲义元数据、任务、切片正文与 ngram 全文索引
                                                     ├─ qdrant  v1.15.1：campusclaw_chunks 集合（余弦，维度取 EMBEDDING_DIMENSIONS）
                                                     ├─ uploads 私有讲义卷
                                                     └─ 课程网关 服务端嵌入与对话接口（两个独立模块、两次调用）
worker（与 api 同镜像，command: [worker]，非 root、只读根文件系统）──> db / qdrant / uploads(只读)
网络：app（internal: true）承载 db、qdrant、api、worker；web 同时接入 app 与 edge，因为当前 Docker 不允许在 internal 网络上发布宿主端口。
```

- **身份**：bcrypt 哈希；256 bit 随机会话；数据库只保存会话 token 的 SHA-256；8 小时过期；HttpOnly / SameSite=Lax cookie；退出立即删除服务器会话。
- **授权**：学生自注册；管理员创建教师；只有班级所有者可管理班级和文件。管理员不自动拥有课堂数据读取权限。
- **班级**：教师所有权 + 学生成员表；唯一邀请码；入班和归档使用行锁协调；成员退出或被移除后，下一次文件请求立即重新检查成员身份。
- **文件**：随机内部名称，原始文件名只用于元数据和下载响应。文件不通过静态目录暴露，PDF 与 Office 都经过同一授权 API。
- **知识库**：新讲义随上传事务进入 MySQL 持久化队列；worker 提取带位置映射的原文，按约 800 字滑动窗口（相邻约 10% 重叠，也可按分隔符或 Markdown 标题分章）切片，切片正文写入 MySQL、向量写入 Qdrant。完整代次构建成功后才原子发布为活动代次，失败重建保留旧索引。检索先用 `class_id` 过滤向量库，再用切片主键回 MySQL 取正文并校验代次仍是已发布代次，并在模型调用后重新确认成员权限。网关未配置或不可用时索引任务记为 `temporary_failure`、检索返回 503，讲义浏览与下载不受影响。
- **溯源**：PDF 页码、PPT 幻灯片、TXT/MD 行号和 Word 提取段落随切片保存，并记录讲义内 1 起始序号与在提取文本中的字符区间。切片 ID 绑定具体代次；重建后旧引用返回失效，删除后级联撤销，向量库中的残留点因代次校验不会被返回。所有来源读取重新鉴权且不缓存。
- **部署**：五个容器（db / qdrant / api / worker / web）；MySQL、Qdrant 和上传卷持久化；健康检查；api 与 worker 以非 root 用户运行，worker 根文件系统与上传卷只读；只有 web 发布 `127.0.0.1:8080`；本地 HTTP 使用非 Secure cookie。

## 当前限制

适用于本机单实例部署。向量检索在 Qdrant 中先按班级过滤，再在合格的切片上精确排序，尚未针对超大班级调整近似索引参数。扫描 PDF、Office 图片、批注、备注、嵌入附件和复杂图表不保证提取；本期不做 OCR。登录限流使用进程内计数，nginx 下以代理连接地址计数，因此属于整个平台的本地节流。公网/多实例部署时需引入可信代理配置和共享限流、HTTPS、文件病毒扫描、备份策略和密码恢复。文件格式签名校验不能证明 Office 文档无恶意宏。

切片正文与向量分处两个存储，写入不是同一事务：向量库中残留的代次失效点由检索侧回表校验丢弃，删除失败的向量点也不会被返回。基础表仍由 `backend/schema.sql` 幂等建立；知识库表由 `backend/migrations/*.sql` 中带版本号的迁移管理，执行记录写入 `schema_migrations`，重复启动不会重建或清空已有表，也没有自动向下删除操作。MySQL 与上传卷需要成对备份；Qdrant 中的向量可以从切片正文重建。迁移前的 PostgreSQL 数据保留在 `database` 卷，仅用于回滚，不要删除，也不要用它承载 MySQL 数据。
