# Design

## Context

动机见 [proposal.md](proposal.md)。当前 `backend/classes.go` 基于所有者和成员表授权，管理员不具有隐式班级读取权；`backend/handouts.go` 在文件保存后写入元数据，下载前检查班级权限，删除时先提交数据库事务再清理文件。`backend/schema.sql` 仅有幂等建表，尚无版本化迁移。

Docker Compose 使用 PostgreSQL 18、Go API 和 nginx，只有网页端口对本机开放，讲义位于私有上传卷。当前没有解析器、模型、worker 或知识索引。原文件不可原地替换；同名重新上传会得到新的讲义 ID。实施须保留这些行为，并兼容已有数据。

## Goals / Non-Goals

**Goals:** 将索引生命周期和既有班级授权连接起来；检索结果以可核对的原文为依据；嵌入故障不阻塞资料管理；单机部署下能够持久化和恢复任务。

**Non-Goals:** 不建设独立多租户向量平台，不接入生成式问答或工具执行，不增加公开文件服务，不把待规划能力显示为已实现。本次仅文档，后续需用户另行要求开始实施。

## Decisions

### 1. 使用 PostgreSQL + pgvector，先做班级内精确检索

将向量与讲义、权限和索引元数据放在同一个数据库，便于事务撤销和备份，避免额外引入 Qdrant/Milvus 及跨库删除一致性。本期使用余弦距离，对已授权班级及当前索引代次的片段进行精确排序；先形成过滤后的候选集合，再计算距离和取 top-k，不能全库 top-k 后过滤。

暂不建立全局 HNSW/IVFFlat 索引；它们的性能收益和过滤召回行为需后续结合数据量验收。官方说明 pgvector 默认支持精确最近邻查询，也提供近似索引；本项目优先选事务一致性与可验证的召回范围。参考：[pgvector 官方文档](https://github.com/pgvector/pgvector)。

### 2. 数据模型区分源文件、构建代次和可用索引

新增有版本号的迁移机制，兼容现有初始化数据库。建议逻辑实体如下，具体字段名在实施时确定：

| 实体 | 关键数据及约束 |
| --- | --- |
| 知识文档 | 唯一 handout_id、class_id、原文件 SHA-256、当前有效代次、最近任务状态；讲义 ID 与班级 ID 使用组合外键保障一致 |
| 索引代次 | 文档 ID、代次 ID、源文件哈希、解析器和分块器版本、嵌入配置 ID、完整构建状态、创建时间 |
| 知识片段 | 代次 ID、class_id、handout_id、不可复用的 chunk_id、顺序、原文、定位范围、向量；归属关系由外键约束 |
| 索引任务 | 文档与构建配置、状态、重试次数、租约、占用令牌、下一次执行时间及安全错误码 |
| 嵌入配置 | 服务类型、模型版本、向量维度、预处理版本、相关性阈值；不在该表保存明文凭证 |

用原文件字节哈希确定来源版本，标题变化不改变源内容版本。向量维度由嵌入配置固定，写入与查询均校验维度和有限数值，拒绝零向量。模型或维度变化创建新配置及新代次，不混合排序；班级内新配置重建完成后再原子切换活动配置，旧索引保留到切换成功。普通重建仅在完整成功时切换文档的活动代次。

### 3. 数据库持久化队列与独立 worker

上传元数据与待处理任务在同一数据库事务提交，模型服务不在上传事务内执行。历史讲义不自动批量消费资源，由所有者选定讲义发起索引。重复请求以文档、内容版本及构建配置去重；主动重建可创建新代次，但同一文档配置同时最多一项有效任务。

worker 从数据库领取带租约的任务，使用占用令牌避免过期 worker 提交，提取后分批向量化并写入不可检索的构建代次。状态为待建立 → 排队 → 解析中 → 向量化中 → 可检索，异常进入失败或不可索引；归档增加暂停标志，并保留恢复所需进度。发布事务锁定班级和讲义，核对源文件仍存在、班级未归档、租约和配置未失效，最后原子切换活动代次。重建失败只更新尝试状态，旧代次仍可检索。

讲义删除事务同步删除知识文档、代次、片段、任务和引用关系；外键级联及发布时存在性检查阻止晚到任务复活资料。物理文件删除失败仍不能使索引可访问。归档与发布使用相同班级行锁协调，归档后不发布新代次，恢复后重新领取暂停任务。临时失败指数退避，默认最多 3 次尝试，永久解析错误不自动重试。

### 4. 提取文本必须同时生成来源映射

| 文件 | 提取及定位方案 |
| --- | --- |
| TXT / MD | UTF-8 原文，以原文件 1 起始行号建立映射；Markdown 本期按文本检索，禁止直接渲染原始 HTML |
| PDF | 按物理页提取文本，保留 1 起始页号；无文本页不做 OCR，混合 PDF 标注只覆盖可提取文字 |
| DOCX | 提取正文与表格文本，按确定的阅读顺序编号为“提取正文段落”；不推断布局页码 |
| PPTX | 按幻灯片和文本块提取，保留 1 起始幻灯片号；图片文字不提取 |
| DOC / PPT | worker 内使用隔离的 LibreOffice 无界面转换为 DOCX / PPTX，再沿用相应定位；界面说明文本经转换提取，DOC 不生成原文件页号 |

正文、表格及幻灯片文本为本期提取范围；批注、演讲者备注、嵌入附件、图片、复杂图表不保证覆盖，界面和使用说明注明。解析器适配器输出文本单元与定位，分块遵循单元边界并保留偏移映射，分块长度按模型 token 上限设置；不得截断超长文件后假称完整。Office 来源面板展示提取上下文并提供原文件下载，无需新增 Office 在线编辑器。

解析在 worker 子进程中进行，不执行宏，不获取文档中的外部资源。初始限制建议：每文件解析 120 秒、展开内容 200 MiB、最多 10000 块、单 worker 并发 1；模型单请求 30 秒。这些上限均配置化，超限显示失败，临时目录在任务结束后清理。解析容器非 root、上传卷只读，模型凭证不传入解析子进程。

### 5. 嵌入服务独立配置，不引入生成模型

由服务端适配器提供批量文本嵌入，默认 Compose 内的本地嵌入服务，不对宿主机公开模型或数据库端口。固定模型版本、维度、预处理和中文检索验收集；部署参数包括 endpoint、model、dimension、timeout，凭证通过环境注入且不提交。远程 endpoint 只能由部署者显式配置，禁止故障时自动转发外部服务。

本地模型的具体发行版本和 CPU 资源配额在实施的依赖验证任务中选定并锁定，不能用随机向量冒充实际功能。模型更新必须保留旧配置查询能力直至新配置切换成功；若旧模型已经不可用，则明确返回服务不可用。测试替身只用于确定性权限和故障测试，最终另跑真实模型中文检索验收。

### 6. API 与授权路径

沿用现有 cookie 会话及 `access()` 的所有者／成员语义，在 API 内集中验证，不信任浏览器传入的角色或文件范围。

| 建议接口 | 行为 |
| --- | --- |
| `POST /api/classes/{classId}/knowledge/search` | 所有者或成员提交 query、可选 top_k（默认 5，上限 20）、可选 handout_ids；query 去空白后最多 1000 个 Unicode 字符 |
| `GET /api/classes/{classId}/knowledge/documents` | 返回本班讲义索引状态、覆盖情况、安全错误码及中文说明 |
| `POST /api/classes/{classId}/knowledge/documents/{handoutId}/index` | 未归档班级所有者发起首次索引、重试或重建；幂等排队返回 202 |
| `GET /api/classes/{classId}/knowledge/chunks/{chunkId}/source` | 重新授权并校验活动代次，返回原文上下文和定位；文件下载与 PDF 预览复用现有授权接口 |

搜索先验证会话、班级权限、输入和所有 handout_ids 的班级归属，再请求查询嵌入。SQL 强制绑定 class_id、活动模型配置、活动代次及讲义存在条件。模型返回后，在新的短事务中重新验证成员身份和来源有效性并执行最终查询；与删除、移除成员协调锁顺序，定义最终查询事务为授权判定时点，该时点前已提交的撤权或删除必须生效。发送到用户浏览器的既有内容无法追溯收回，不承诺消除网络传输中的竞态。

无会话 401；无班级权限 403；授权班级内不存在的资源或跨班级讲义／片段 ID 统一 404；归档时写索引或旧代次引用 409；输入错误 400；模型超时、配置不兼容、数据库检索故障 503。无索引或无相关命中正常返回 200，并用 `no_ready_documents` / `no_matches` 区分；部分覆盖返回数量及提示。结果包括引用、原文、余弦相似度（不叫置信度），只返回达到当前模型配置阈值的片段。

本期不缓存搜索结果或引用正文，响应使用 `Cache-Control: no-store`；日志只记录请求标识、耗时、数量和安全错误码，不默认记录查询或讲义正文。后续如引入缓存，必须将班级、活动版本和权限撤销纳入失效机制。

### 7. 来源展示与界面状态

React 班级详情增加“知识库”，查询结果显示讲义名称、片段和位置，来源面板给出上下文、版本和授权文件链接。PDF 可用现有预览链接加页码锚点，其余格式展示可核对的文本定位并下载原文件。引用由 class_id + chunk_id 指向不可复用代次，重建后旧引用 409，删除后 404，不重定向至相似内容。

界面显示待建立、构建进度阶段、失败、不可索引和归档暂停；学生不显示管理按钮但后端独立校验。切换班级清空状态并取消或忽略旧请求，来源安全转义。白色主表面、红色操作重点，所有提示中文。只呈现真实索引状态，不添加聊天入口。

## Risks / Trade-offs

- [精确向量排序随班级资料增多变慢] → 先限制结果和任务规模，记录中文样例库检索延时，再按实测考虑带班级过滤的近似索引；本期不承诺未经测量的并发指标。
- [Office 转换顺序或 PDF 多栏文本存在偏差] → 固定解析版本，以含表格、多栏、分页、中文的样例验收定位；提供原文件核对，不伪造页码。
- [扫描件或部分不可提取内容降低覆盖] → 明确标注文字覆盖范围，OCR 作为后续独立变更。
- [本地模型占用内存、启动下载耗时] → CPU 运行与模型持久化卷、就绪检查和资源配置纳入部署验收，依赖不可用只影响检索。
- [解析器处理不可信文件] → 隔离子进程、禁宏与外部资源、只读源卷、超时与展开限额；在实施阶段验证限制实际生效。
- [更换数据库镜像破坏既有数据] → 保持 PostgreSQL 18 及卷挂载布局，使用兼容的固定 pgvector 版本，迁移前备份，先验证副本恢复。

## Migration Plan

1. 实施时先选定并锁定兼容 PostgreSQL 18 的 pgvector 构建、解析工具和本地嵌入服务；记录资源需求及许可证。可基于兼容的 PostgreSQL 18 镜像构建扩展，避免隐式升级主版本。
2. 备份数据库和上传卷，在副本验证恢复；引入迁移版本表，安装扩展并增量添加知识库表、约束及索引，验证重复启动无破坏性操作。
3. 部署 worker 与内部嵌入服务，模型缓存使用持久化卷；新 API 与界面在服务就绪后启用。已有讲义显示待建立，所有者主动回填。
4. 验证容器重启恢复任务、数据库与模型卷持久化，执行授权、来源、删除、故障及真实检索验收，将实际结果写入验证文档。
5. 回滚先停 worker、关闭新入口并部署旧 API／前端，保留新表但不使用，不删原卷；若需恢复数据库，使用已验证且与上传卷配对的备份。不通过 `down -v` 或重新初始化清空数据。

## Open Questions

- 实施时依据本机内存与中文样例，锁定本地嵌入模型的具体版本、维度及相关性阈值；不得改变本地默认、权限边界和逐条溯源的验收要求。
- DOC/PPT 转换和 PDF 文本提取工具的具体版本，在兼容性样例通过后固定；若现有方案无法满足定位规约，先修订设计再实施替代方案，不静默缩减支持格式。
