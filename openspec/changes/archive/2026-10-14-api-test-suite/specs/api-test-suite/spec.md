# Spec Delta

## Purpose

规定仓库内接口测试套件的组织与质量要求：一个接口一个脚本、按 URL 组织、一键运行并产出不提交的 HTML 报告，且每条用例都要核对返回内容与数据库状态是否一致。

## ADDED Requirements

### Requirement: 用例组织与命名
套件 SHALL 为每个受测 HTTP 操作提供一个独立可运行的脚本，脚本路径 SHALL 由 URL 与 HTTP 方法决定，例如 `cases/api/login/POST.py` 对应 `POST /api/login`。脚本 SHALL 既能被运行器自动发现并执行，也能单独运行。新增脚本 MUST NOT 需要修改运行器代码。

#### Scenario: 按 URL 组织的脚本被自动发现
- **WHEN** 在 `cases/api/classes/{id}/knowledge/search/POST.py` 新增一个脚本
- **THEN** `run_all.py` 无需改动即可发现并执行它

#### Scenario: 单脚本独立运行
- **WHEN** 直接运行某个用例脚本
- **THEN** 它完成自己的前置准备、断言与清理，并输出通过或失败

### Requirement: 一键运行与报告
套件 SHALL 提供单一入口一键运行全部用例，SHALL 生成自包含的 HTML 报告（不依赖外网资源），报告 SHALL 写入被版本控制忽略的目录。运行入口 SHALL 以退出码反映整体结果。

#### Scenario: 全部通过
- **WHEN** 运行入口执行全部用例且全部通过
- **THEN** 退出码为 0，报告中每条用例标记为通过

#### Scenario: 存在失败
- **WHEN** 任一用例断言失败
- **THEN** 退出码非 0，报告标注失败用例、失败断言与期望/实际差异

#### Scenario: 报告不进入版本控制
- **WHEN** 生成报告后查看版本控制状态
- **THEN** 报告文件与虚拟环境目录不出现在待提交列表中

### Requirement: 断言深度
每条用例 SHALL 在断言状态码之外核对响应内容，并 SHALL 核对数据库中的对应状态（例如登录后会话行存在、上传后讲义行与班级关联正确、提问后消息行与出处落库）。仅断言状态码的用例 MUST NOT 视为通过。

#### Scenario: 响应与数据库一致
- **WHEN** 创建会话并发送一条消息后查询数据库
- **THEN** 会话行、用户消息行与助手消息行都存在，且消息顺序与接口返回一致

#### Scenario: 数据库不一致导致失败
- **WHEN** 响应正常但数据库状态与预期不符
- **THEN** 该用例失败并指出差异所在的表与字段

### Requirement: 最低覆盖范围
套件 SHALL 至少覆盖：登录、班级知识库检索、提示词或技能读写、创建会话并发送一条消息（含流式回答与出处落库）。

#### Scenario: 覆盖清单可见
- **WHEN** 运行入口完成一次执行
- **THEN** 报告中能逐条看到上述四类用例及其结果

#### Scenario: 流式回答被验证
- **WHEN** 用例发送一条消息并读取流式响应
- **THEN** 断言收到一个以上增量事件、结束事件与出处列表，并核对助手消息已落库

### Requirement: 环境与清理
套件 SHALL 复用仓库 `.env` 中的连接与账号配置，SHALL 使用独立的临时数据，并在结束后清理自身创建的账号、班级与文件。重复运行 SHALL 得到一致结果，MUST NOT 依赖执行顺序或历史残留数据。

#### Scenario: 连续运行两次
- **WHEN** 连续执行两次运行入口
- **THEN** 两次结果一致，且第二次不因上一次的残留数据而失败

#### Scenario: 清理彻底
- **WHEN** 一次运行结束后查询数据库
- **THEN** 用例创建的临时教师、学生、班级与讲义均已删除

#### Scenario: 缺少依赖时给出可执行提示
- **WHEN** 运行环境缺少所需 Python 库
- **THEN** 运行入口打印安装命令并以非零退出码结束，而不是抛出难以理解的堆栈
