# Design

## Context

动机见 [proposal.md](proposal.md)。本变更假设 `mysql-qdrant-platform` 与 `knowledge-retrieval-modes` 已落地：检索接口支持 `hybrid` 并返回带切片序号与字符区间的命中，课程网关的嵌入客户端与配置校验已存在，来源读取接口可打开命中切片。前端已有请求序号机制用于丢弃过期响应，知识库页面已有模式选择与命中列表。

## Goals / Non-Goals

**Goals:**

- 先检索后生成，没有依据时不产生任何生成内容。
- 回答与出处可逐条对应，用户能从回答跳到原文。
- 生成模块只使用检索模块组装的输入，不自行检索。

**Non-Goals:**

- 不做流式输出、不做服务端对话历史持久化、不做多轮意图改写与重排序。
- 不引入编排框架；提示组装由 Go 服务完成。
- 不修改检索接口的既有契约（本变更只新增问答接口）。

## Decisions

### 1. 新增独立问答接口，而不是在检索接口上加开关

问答与检索的失败模式不同：检索失败是「没有依据」，问答失败还包括「有依据但对话模型不可用」。合并成一个接口会把两种状态塞进同一个响应，前端也无法分别表达加载与错误。因此新增 `POST /api/classes/{id}/knowledge/ask`，响应为 `{status, answer, citations[]}`，检索接口保持只返回命中。

替代方案：在检索请求上加 `generate=true`（响应契约混杂、缓存与错误语义不清）。被否。

### 2. 固定顺序与上限：先检索，命中才生成，最多 4 条

流程固定为：以用户当前这一句执行本班混合检索 → 无命中则短路返回「资料中未找到相关内容」与空 `citations`，且不构造对话请求 → 有命中则取前 4 条交给对话模块。上限 4 条既控制提示长度，也让编号范围有限，便于校正与展示。默认超时与提示长度上限可配置。

### 3. 提示只包含标题、序号、正文与对话轮次

交给对话模块的内容：每条的「材料标题 + 切片序号 + 切片正文」，用户最新一句提问，以及此前的若干轮对话（默认最近 6 条、总量限长）。历史轮次由前端在内存中维护并随请求提交，服务端只做角色与长度校验，不落库。任何角色为 system 的消息一律丢弃。MUST NOT 传入向量分量、Qdrant 原始点数据或其他班级的切片。

### 4. 引用由服务端校正，出处列表只来自命中

模型输出是不可信文本，可能写出超出范围的编号，也可能提到未命中的材料。服务端在返回前解析回答中的 `[n]`：只把落在命中范围内的编号当作引用；超出范围的编号不呈现为引用（按普通文本处理并记录安全日志）。`citations` 始终由服务端从命中切片生成，与回答文本无关，因此即使用户点击的出处也一定是真实命中的切片。页面出处列表顺序与 `citations` 顺序一致，编号即数组下标 + 1。

### 5. 响应约束

一次性 JSON 响应，不开启流式；沿用 `Cache-Control: no-store`；网关超时或返回错误时返回 503 且不返回部分回答；无命中路径返回 200 与固定文案。响应中不得出现网关地址、密钥、向量分量或内部存储路径。

### 6. 界面

知识库页面在命中区块之上增加回答区块与出处列表（切片序号、字符区间、摘录、打开材料）。无命中时只显示「资料中未找到相关内容」，不展示回答区块。切换班级或发起新检索时清空旧回答，沿用现有请求序号机制忽略过期响应；回答与摘录一律作为纯文本渲染。

## Risks / Trade-offs

- [模型编造引用或写成与出处无关的结论] → 服务端校正编号范围，出处列表只取命中切片；提示中明确要求使用给定编号；验收时逐条核对回答与出处。
- [提示过长导致超时或截断] → 限制为前 4 条、历史限长并可配置；记录实际提示长度与耗时。
- [无命中路径被意外调用生成模型] → 用测试替身断言该路径对话网关零调用，并纳入集成检查。
- [连续追问把旧话题带入新问题] → 每轮仍以最新一句重新检索本班切片，历史只作为附加上下文，不参与检索。
- [网关不可用影响体验] → 返回明确错误并保留检索与下载能力；用户仍可直接使用检索模式查看原文。

## Migration Plan

1. 新增对话客户端与配置项，先用测试替身验证错误与超时路径。
2. 新增问答接口与提示组装，接入既有 hybrid 检索，覆盖无命中短路。
3. 前端增加回答区块与出处列表，处理加载、错误与无命中状态。
4. 用标注问题集做完整验收：有依据的问题检查引用可核对，无关问题检查零调用与固定文案。
5. 更新 `docs/api.md`、`docs/architecture.md`、`docs/knowledge-base.md`、`docs/verification.md` 与 `AGENTS.md` 中问答相关描述。

## Open Questions

- 课程网关提供的对话模型名与可用上下文长度（通过配置项提供，缺失时问答接口按模型不可用处理，不影响其他验收项）。
