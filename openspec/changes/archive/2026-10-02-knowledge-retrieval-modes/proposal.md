# Proposal

## Why

底座换成 MySQL + Qdrant 之后，检索能力仍然只有单路向量：问句里的词明明直接出现在原文中，也可能因为表述差异而漏检；系统也没有把关键字与语义两路结果合并的手段。本课要求按提问形态提供 keyword / vector / hybrid 三种模式，并给出统一、可回溯的结果契约。本变更交付这三项能力与结果契约，不涉及生成回答。

## What Changes

- 检索接口新增 `mode`：`keyword` 只查询 MySQL 中文全文索引且不调用嵌入模块；`vector` 把问句转换为向量后按余弦排序并丢弃低于 0.35 的候选；`hybrid` 同时执行两条路径，两路各自按绝对分数过滤后按 RRF（k = 60）融合，两路均命中的切片排序更靠前。默认模式为 `hybrid`。
- 检索结果统一为 `hits`，每条包含材料标题、切片序号、字符区间、摘录与定位；摘录取自关系库中的切片正文。
- 无相关结果时返回「资料中未找到相关内容」且 `hits` 为空，MUST NOT 以相关度明显偏低的切片凑数。
- 检索的班级标识只取自登录会话与请求路径；请求体、查询字符串或请求头中另行携带的班级编号在解析后丢弃。跨班级检索表现为本班内无命中（HTTP 200、空列表），不以 403 或 404 暗示其他班级存在该资料。
- 知识库页面增加检索模式选择与结果模式标注，并在无命中时显示统一文案。

## Capabilities

### New Capabilities

无。本变更只扩展既有检索能力，不引入新能力。

### Modified Capabilities

- `class-knowledge-search`: 「单班级服务端授权」补充班级标识丢弃与跨班无命中语义；「有边界的语义检索」扩展为三种模式与统一结果契约；「区分无结果与不可用」明确无命中文案与不凑数；「班级内检索界面」增加模式选择与无命中提示。
- `knowledge-provenance`: 「每条结果具备完整出处」补充切片序号、在提取文本中的字符区间，以及摘录取自关系库的约束。

## Impact

- 后端：检索接口的输入校验与两条新增检索通路的实现，以及全文索引相关度与向量余弦的分数契约。
- 前端：新增模式选择与结果模式标注；结果字段由 `results` 改为 `hits`，类型定义与渲染同步调整。
- 验收脚本：`scripts/knowledge-test.mjs` 与集成检查需按新字段与三种模式更新断言。
- 依赖：本变更依赖 `mysql-qdrant-platform` 先落地（MySQL 全文索引、Qdrant 集合、切片序号与字符区间、课程网关嵌入）。
- 边界：问答、`[1]` 引用与出处列表由 `knowledge-answer-citations` 承担，本变更不调用对话模型。
