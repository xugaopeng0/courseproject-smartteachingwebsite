# Design

## Context

动机见 [proposal.md](proposal.md)。本变更假设底座变更 `mysql-qdrant-platform` 已落地：切片正文与全文索引在 MySQL、向量在 Qdrant 集合 `campusclaw_chunks`、嵌入经服务端课程网关、切片已带序号与字符区间、单路向量检索（阈值 0.35）可用且响应结构未变。当前检索请求体为 `{query, top_k, handout_ids}`，响应字段为 `results`，前端通过请求序号丢弃过期响应。

## Goals / Non-Goals

**Goals:**

- 三种模式共用一套结果契约与授权路径，模式差异只体现在候选来源与排序。
- 结果可逐条回溯到原文位置（材料标题、切片序号、字符区间、摘录）。
- 无相关结果时语义明确，不以外观凑数。

**Non-Goals:**

- 不生成回答、不调用对话模型、不展示出处以外的生成内容（属 `knowledge-answer-citations`）。
- 不实现重排序（交叉编码器）、流式输出、跨班级检索与结果缓存。

## Decisions

### 1. 三模式的分数契约

| 模式 | 候选来源 | 绝对过滤 | 排序 |
| --- | --- | --- | --- |
| `keyword` | MySQL `MATCH ... AGAINST` | 至少命中一个二字 token | 全文相关度降序 |
| `vector` | Qdrant（带班级过滤） | 余弦 ≥ 0.35 | 余弦降序 |
| `hybrid` | 两条路径各自执行 | 各自通过上述绝对过滤，各取前 50 条 | RRF（k = 60）名次分降序 |

名次分只用于排序，不作为相关性阈值，也不对外暴露为「相关度」。关键字路径的绝对过滤以「至少命中一个 token」为下限，实施后用标注问题集检查是否带进明显低相关结果，必要时提高下限；最终取值写入验收记录。

替代方案：对关键字分数设一个固定阈值（如 1.0）——MySQL 相关度分数随语料变化，固定值不可移植，故先以「至少命中一个 token」为下限并用实测调参。

### 2. 默认模式取 hybrid

本课要求问答链路以混合检索为依据，界面默认与之一致可减少口径分叉；请求可显式指定 `keyword` 或 `vector`。既有调用方若不传 `mode`，行为从「单路向量」变为「混合」，排序可能变化，因此验收需用标注集对比三模式召回，而不是假定结果与旧版一致。

### 3. 结果契约统一为 hits

每条命中包含：切片标识、材料标题、原始文件名、切片序号、字符区间、摘录、定位信息与所用模式。摘录取自 MySQL 的切片正文；相似度只在 `vector` 与 `hybrid` 的调试字段中出现，MUST NOT 被描述为事实正确概率。字段由 `results` 改名为 `hits`，前端类型、渲染与验收脚本同步修改。

### 4. 无命中与不可用分开表达

沿用既有的状态区分：`no_ready_documents`（本班尚无可用索引）、`no_matches`（有索引但没有达到阈值的命中）。`no_matches` 时统一返回「资料中未找到相关内容」且 `hits` 为空；网关故障或维度不匹配仍返回 503，不伪装成零条命中。关键字模式不依赖网关，网关故障时仍可返回结果。

### 5. 班级标识只认会话与路径

检索请求的班级来自请求路径并复用 `access()`；请求体中出现的 `class_id` 等字段被显式丢弃而不是报错——现有 `decode()` 使用 `DisallowUnknownFields`，会把它当成非法请求返回 400，本变更需为检索请求放宽这一处并忽略该字段，使「解析后丢弃」成为可验收的行为。跨班级检索在语义上是本班内无命中，不返回 403 或 404。

### 6. 界面

知识库页面增加模式选择（默认 hybrid），结果区标注本轮模式，并统一无命中文案。沿用现有请求序号机制忽略过期响应：切换班级或模式时清空结果与来源面板，旧请求返回不写入状态。索引管理与切片策略入口仍只对所有者显示，服务端独立校验。

## Risks / Trade-offs

- [关键字二字切分带来噪声] → 用标注集统计 keyword 与 hybrid 的低相关命中占比，必要时提高关键字分数下限并记录取值。
- [字段改名影响既有前端与脚本] → 一次性同步前端类型、`scripts/knowledge-test.mjs` 与集成检查，并在全量检查中确认无残留 `results` 引用。
- [默认模式改变既有排序] → 用同一标注集对三模式做召回对比，把差异写入验证文档，而不是把旧排序当作基准。
- [两路候选数量不对称] → 每路融合前各取前 50 条，避免单路以数量淹没另一路；该上限可配置。
- [关键字模式在网关故障时仍可用，可能掩盖故障] → 故障状态按模式分别表达，`vector` 与 `hybrid` 明确报错，不用关键字结果掩盖。

## Migration Plan

1. 先在接口层加入 `mode` 与 `hits`，同时保留输入校验与授权路径不变。
2. 实现 keyword 与 hybrid 两条通路，并补齐 vector 的模式入口与阈值断言。
3. 同步前端类型与界面，更新 `scripts/knowledge-test.mjs` 与集成检查。
4. 用标注集做三模式召回对比，确认 hybrid 达到「≥20 条中 ≥18 条在前 5 条命中目标切片」，记录阈值与耗时。
5. 更新 `docs/api.md`、`docs/knowledge-base.md` 与 `docs/verification.md` 的检索部分。
